# 지하주차장 협동 공포 게임 — 하위 프로젝트 1: 라운드 1회 설계

- 작성일: 2026-10-02
- 상태: 설계 승인 완료 (섹션 1~6), 스펙 문서 검토 대기
- 작업명: `basement-horror`

## 0. 개요

웹 브라우저(PC)에서 친구 1~4명이 링크 하나로 모여 플레이하는 2D 탑다운 협동 서바이벌 공포 게임이다.
리썰 컴퍼니의 "들어가서 폐품을 모아 제시간에 빠져나온다"는 핵심 루프를 한국형 공포(오래된 아파트 지하주차장, 구전 괴담) 배경으로 옮긴다.

### 0.1 목적과 성공 기준

| 항목 | 내용 |
|---|---|
| 1차 목적 | 친구들과 실제로 모여 재밌게 플레이하는 것. 다른 사용자 유입도 고려한다 |
| 이번 하위 프로젝트의 성공 기준 | 친구 2~4명이 각자 PC 브라우저에서 초대 링크로 들어와 라운드 1회를 처음부터 끝까지 플레이할 수 있고, 끝난 뒤 "한 판 더"를 누를 만큼 재미있다 |

### 0.2 확정된 결정

| 항목 | 결정 |
|---|---|
| 장르 | 2D 탑다운 서바이벌 공포, 협동 |
| 플랫폼 | PC 브라우저 우선(키보드·마우스). 모바일은 입력 추상화와 화면 크기 대응 같은 구조만 준비한다 |
| 개발 환경 | 사용자 PC의 Claude Code Remote Control 세션에서 주 개발과 플레이 테스트를 하고, 폰으로 원격 진행한다 |
| 세계관 | 한국형 공포. 실제 분위기(80~90년대 아파트 구조와 소품)를 재현하되 지명과 건물명은 가상으로 하고, 구전 괴담을 공포 요소로 쓴다 |
| 첫 맵 | 오래된 아파트 지하주차장 (지하 1층, 지하 2층) |
| 인원 | 1~4명. 인원에 따라 난이도를 조절한다 |
| 사망 | 유령 모드 |
| 몬스터 | 추적형(옛 경비원) + 시선형("무궁화 꽃이 피었습니다" 귀신) |
| 라운드 | 수거 트럭으로 폐품을 반복 운반한다. 새벽 4시에 트럭이 출발한다 |
| 소통 | 게임 안 음성채팅은 없다(디스코드 등 외부 음성을 쓴다고 가정). 퀵챗과 핑을 제공한다 |
| 입장 | 방 코드와 초대 링크. 모르는 사람과의 자동 매칭은 없다 |
| 그래픽 | 도형 + 조명 효과로 시작하고, 스프라이트로 교체할 수 있는 구조로 만든다 |
| 기술 | TypeScript, 서버 판정 방식(Colyseus), Canvas 2D, Vite, Vitest, Playwright |

### 0.3 하위 프로젝트 로드맵

각 하위 프로젝트는 각자 스펙 → 계획 → 구현 사이클을 거친다. 이 문서는 1번만 다룬다.

| 순서 | 하위 프로젝트 | 내용 |
|---|---|---|
| **1** | **라운드 1회 (이 문서)** | 지하주차장 맵, 몬스터 2종, 트럭 운반, 유령 모드, 1~4인 온라인 협동 |
| 2 | 할당량 사이클과 상점 | 여러 라운드에 걸친 할당량, 장비 구매 |
| 3 | 그래픽 교체 | 픽셀 아트 스프라이트, 효과음 교체 |
| 4 | 공개 호스팅 | 클라우드 서버 배포, 공개 접속 주소 |
| 이후 | 확장 | 맵 추가(폐교, 폐병원), 매복형 몬스터, 모바일 터치, 수익화, 앱인토스 이식 |

### 0.4 이번 범위에서 제외

광고, 결제, 계정과 로그인, 상점과 장비, 할당량 사이클, 모바일 터치 조작, 전기실 전력 복구, 매복형 몬스터, 양손 들기 폐품, 키 변경, 공개 매칭, 서버 쪽 정보 가리기(치팅 방지), 클라우드 배포.

## 1. 전체 구조

### 1.1 저장소 구성

npm workspaces 모노레포로 구성한다.

| 패키지 | 역할 | 의존 대상 | 테스트 |
|---|---|---|---|
| `packages/shared` | 게임 규칙 전체. 순수 TypeScript이며 네트워크와 화면을 모른다 | 없음 | Vitest 단위·시나리오 테스트 (TDD 핵심) |
| `packages/server` | Colyseus 방. 접속과 퇴장을 관리하고, 입력을 모아 `shared` 규칙을 고정 주기로 실행해 결과를 전송한다. 빌드된 클라이언트도 같은 포트로 제공한다 | `shared`, Colyseus | 가짜 클라이언트를 쓰는 통합 테스트 |
| `packages/client` | 로비, 입력, Canvas 렌더링(조명 포함), HUD, 소리 | `shared`, Colyseus 클라이언트, Vite | 순수 함수 단위 테스트 + Playwright E2E |

### 1.2 `shared` 모듈

| 모듈 | 책임 |
|---|---|
| `config` | 모든 조정 가능한 수치 (2장의 초기값) |
| `rng` | 시드가 있는 결정적 난수 |
| `map` | 타일 격자(벽, 바닥, 기둥, 차량, 계단, 트럭 구역), 구역, 스폰 위치, 고정 조명 위치. 맵 데이터는 JSON이다. 맵 검증 함수를 포함한다 |
| `pathfinding` | 타일 격자 A* |
| `movement` | 이동, 걷기와 뛰기, 스태미나, 무게에 따른 감속, 벽과 차량 충돌, 끼임 해소 |
| `vision` | 벽 선분 기반 시선 계산, 손전등 부채꼴 판정, 가시 다각형 계산. 렌더링과 시선형 몬스터가 함께 쓴다 |
| `noise` | 소리 발생과 반경 판정 |
| `monsters/stalker` | 추적형 상태 기계 |
| `monsters/watcher` | 시선형 규칙 |
| `items` | 폐품 정의, 배치, 소지 칸, 줍기와 버리기 |
| `round` | 게임 시계, 트럭 적재, 조기 출발, 04:00 출발, 인원별 난이도, 결과 판정 |
| `ghost` | 유령 이동, 형광등 깜빡이기, 쿨타임 |
| `comms` | 퀵챗 목록, 핑, 쿨타임 |
| `input` | 입력(행동) 타입과 검증·범위 제한 함수 |
| `step` | `step(world, inputs, dt)` → 다음 world. 처리 순서를 고정한다(5.4) |

### 1.3 핵심 원칙

| 원칙 | 내용 |
|---|---|
| 고정 주기 | 서버가 초당 20회(50ms) `step`을 실행한다 |
| 결정성 | 같은 시드와 같은 입력이면 같은 결과가 나온다. 시간은 `step`의 `dt`로만 받는다 |
| 규칙의 단일 위치 | 규칙은 `shared`에만 둔다. 서버는 실행하고, 클라이언트는 예측 이동과 시야 계산에만 같은 코드를 쓴다 |
| 교체 가능한 그래픽 | 렌더러는 엔티티 종류만 받는다. 도형으로 그릴지 스프라이트로 그릴지는 렌더러의 그리기 표가 결정한다 |
| 행동 단위 입력 | 입력은 키가 아니라 행동(이동 방향, 뛰기, 조준 각도, 손전등, 상호작용, 버리기, 칸 선택, 핑, 퀵챗, 깜빡이기)으로 전달한다 |

## 2. 게임 규칙

아래 수치는 모두 `shared/config`의 초기값이며 플레이 테스트로 조정한다.

### 2.1 맵

| 항목 | 규칙 |
|---|---|
| 크기 | 층당 약 60×40 타일, 타일 1칸 = 32px |
| 층 | 지하 1층(B1), 지하 2층(B2). 계단실 타일로 층을 이동한다 |
| 구역 | 주차 구역(기둥, 방치 차량), 엘리베이터 홀과 계단실, 보일러실, 전기실, 세대별 창고, 경비실, 분리수거장 |
| 분위기 | B2는 B1보다 고정 조명이 적고 어둡다 |
| 트럭 | B1 출입구에 있다. 트럭 구역은 이동 가능한 직사각형 영역이다 |
| 시작 위치 | 모든 플레이어는 트럭 구역에서 시작한다 |
| 고정 조명 | 맵 JSON에 위치와 반경을 둔다. 일부는 원래 깜빡인다 |

### 2.2 시간

| 항목 | 규칙 |
|---|---|
| 게임 시계 | 00:00 → 04:00. 실제 12분이다(게임 1분 = 실제 3초) |
| 00:30 | 시선형 등장 |
| 03:00 | 남은 고정 조명의 절반이 꺼지고, 추적형 속도 +10% |
| 03:50 | 트럭 경적(10분 전 경고) |
| 04:00 | 트럭 자동 출발 |

### 2.3 플레이어

| 항목 | 규칙 |
|---|---|
| 이동 | 걷기 초당 3타일, 뛰기 초당 5타일 |
| 스태미나 | 뛰기 최대 5초. 걷거나 멈추면 회복한다(초당 1초분). 0이면 뛸 수 없다 |
| 체력 | 2. 0이 되면 사망한다 |
| 주변 빛 | 반경 1.5타일. 항상 켜져 있다 |
| 손전등 | 마우스 방향으로 60° 부채꼴, 사거리 8타일, 벽에 막힌다. 켜고 끌 수 있다. 배터리 180초이며 켜져 있을 때만 닳는다. 트럭 구역에 있으면 최대치로 충전된다. 0이면 켤 수 없다 |
| 소음 반경 | 걷기 1.5타일, 뛰기 8타일, 폐품 버리기 6타일. 소리는 벽을 통과한다(직선 거리로 판정) |
| 소지 | 3칸. 총무게 1kg당 이동속도 1% 감소, 최대 30% |
| 층 | 다른 층의 엔티티는 보이지도 들리지도 않는다 |

### 2.4 폐품

| 항목 | 규칙 |
|---|---|
| 개수 | 라운드 시작 시 약 25개를 무작위 배치한다(시드 사용) |
| 종류 예시 | 고철, 구리 전선, 낡은 자전거, 폐가전, 녹슨 공구함 |
| 가치 | 10~80 |
| 무게 | 2~15kg |
| 총액 | 배치된 폐품 가치 합계는 해당 인원 목표액의 약 1.8배 |
| 배치 위치 | 맵 JSON의 폐품 후보 칸 중에서 고른다 |

### 2.5 인원별 난이도

| 인원 | 목표액 | 추적형 | 시선형 |
|---|---|---|---|
| 1명 | 150 | 1마리 (속도 -15%), B2 배치 | 1마리 |
| 2명 | 250 | 1마리, B2 배치 | 1마리 |
| 3명 | 350 | 2마리, 층마다 1마리 | 1마리 |
| 4명 | 450 | 2마리, 층마다 1마리 | 1마리 |

인원은 라운드 시작 시점의 참가자 수로 정한다.

### 2.6 추적형: 옛 경비원

| 상태 | 행동 | 전환 조건 |
|---|---|---|
| 배회 | 맵 JSON의 경로 지점을 돈다 (초당 2.5타일) | 소리 감지 → 조사. 플레이어 발견 → 추격 |
| 조사 | 소리 난 지점으로 이동 (초당 3.5타일) | 도착 후 발견 못 함 → 배회. 발견 → 추격 |
| 추격 | 대상 플레이어를 A*로 쫓는다 (초당 4.5타일) | 대상이 5초 연속 시야에서 벗어남 → 수색 |
| 수색 | 마지막으로 본 지점 주변 5초 탐색 | 발견 → 추격. 5초 경과 → 배회 |
| 공격 후 | 닿은 플레이어에게 1 피해를 주고 3초간 반대 방향으로 물러난다 | 3초 후 → 수색 |

| 판정 | 정의 |
|---|---|
| 발견 | 살아 있는 플레이어가 6타일 안에 있고 벽에 가리지 않거나, 어떤 플레이어의 손전등 부채꼴이 추적형에 닿음(그 손전등의 주인이 대상이 된다) |
| 소리 감지 | 소음 반경 안에 추적형이 있음 |
| 층 | 배치된 층에만 머문다 |
| 속도 | 1인 보정(-15%)과 03:00 보정(+10%)은 곱한다 |

### 2.7 시선형: 무궁화 귀신

| 규칙 | 내용 |
|---|---|
| 등장 | 00:30에 살아 있는 플레이어 모두에게서 가장 먼 이동 가능 칸에 나타난다 |
| 정지 | 같은 층의 살아 있는 플레이어 중 누구든 손전등 부채꼴 안에 시선형이 있고 벽에 가리지 않으면 그 틱에 움직이지 않는다. 유령은 해당하지 않는다 |
| 이동 | 정지 상태가 아니면 가장 가까운(경로 길이 기준) 살아 있는 플레이어에게 A*로 접근한다. 초당 5.5타일 |
| 층 | 계단을 이용해 층을 이동한다 |
| 공격 | 닿은 플레이어는 즉사한다 |
| 기타 | 소리에 반응하지 않는다. 죽일 수 없다. 움직이는 동안 끌리는 소리를 낸다 |
| 경로 없음 | 그 자리에서 1초 대기 후 다시 탐색한다 |

### 2.8 트럭과 라운드 종료

| 상황 | 규칙 |
|---|---|
| 적재 | 트럭 구역에서 상호작용하면 소지한 폐품을 모두 싣는다. 트럭 총액은 모두에게 공개된다 |
| 조기 출발 | 살아 있는 플레이어 전원이 트럭 구역에 있을 때, 그중 누구든 상호작용을 3초간 누르면 출발한다 |
| 04:00 출발 | 트럭 구역 밖의 살아 있는 플레이어는 사망한다 |
| 전원 사망 | 즉시 실패. 트럭 총액도 무효다 |
| 성공 판정 | 트럭이 출발했고 트럭 총액 ≥ 목표액이면 성공, 아니면 실패 |
| 결과 화면 | 성공·실패, 트럭 총액, 목표액, 플레이어별 운반액과 생존 여부 |

### 2.9 사망과 유령

| 항목 | 규칙 |
|---|---|
| 사망 시 | 소지한 폐품은 그 자리에 떨어진다 |
| 유령 이동 | 초당 6타일, 벽 통과, 계단으로 층 이동 |
| 유령 가시성 | 몬스터와 살아 있는 플레이어에게 보이지 않는다 |
| 형광등 깜빡이기 | 반경 3타일 안의 고정 조명을 1.5초간 깜빡이게 한다. 쿨타임 10초 |
| 제한 | 폐품, 문, 트럭과 상호작용할 수 없다 |

### 2.10 퀵챗과 핑

| 항목 | 규칙 |
|---|---|
| 퀵챗 | "여기로", "도와줘!", "폐품 있음", "도망쳐!", "비춰줘!", "트럭으로". 모든 참가자에게 보인다. 쿨타임 1초 |
| 핑 | 마우스 위치에 3초간 표시. 쿨타임 3초. 살아 있는 사람과 유령 모두 사용한다 |

## 3. 네트워크와 동기화

### 3.1 입장 흐름

| 단계 | 동작 |
|---|---|
| 첫 화면 | 닉네임 입력(1~10자, 앞뒤 공백 제거) |
| 방 만들기 | 무작위 6자리 영숫자 방 코드와 초대 링크(`/?room=CODE`) 생성. 링크 복사 버튼 |
| 링크 입장 | 초대 링크로 열면 닉네임 입력 후 바로 대기실로 |
| 대기실 | 참가자 목록. 방장(방을 만든 사람)만 시작할 수 있다. 1명이어도 시작할 수 있다 |
| 라운드 | 시작되면 방이 잠긴다. 진행 중에는 입장할 수 없다 |
| 결과 | "한 판 더"를 누르면 같은 방, 같은 멤버로 대기실로 돌아간다 |
| 방장 | 방장이 나가면 남은 사람 중 가장 먼저 들어온 사람이 방장이 된다 |
| 정원 | 4명 |

### 3.2 데이터 흐름

| 방향 | 내용 | 방식 |
|---|---|---|
| 클라이언트 → 서버 | 행동 입력. 입력마다 순번을 붙인다 | 메시지, 초당 30회(33ms)로 묶어 전송. 일회성 행동(상호작용, 핑 등)은 다음 전송에 포함 |
| 서버 → 클라이언트 | 지속 상태: 플레이어(위치, 층, 방향, 손전등, 배터리, 체력, 스태미나, 생존/유령, 소지품), 몬스터(위치, 층, 상태), 바닥 폐품, 트럭 총액, 게임 시계, 고정 조명 상태, 방 단계(대기·진행·결과) | Colyseus 상태 동기화, 50ms마다 변경분 |
| 서버 → 클라이언트 | 일회성 이벤트: 퀵챗, 핑, 깜빡임, 피격, 사망, 경적, 라운드 종료 | 메시지 |
| 맵 | 맵 JSON은 `shared`에 포함된다. 서버는 맵 ID만 보낸다 | |
| 처리 결과 | 서버는 플레이어별로 마지막으로 처리한 입력 순번을 상태에 포함한다 | |

정보 가리기: 서버는 모든 상태를 모두에게 보내고, 클라이언트가 보이지 않아야 할 것(빛 밖의 몬스터와 폐품, 살아 있는 사람에게는 유령)을 숨긴다.

### 3.3 지연 처리

| 대상 | 처리 |
|---|---|
| 내 캐릭터 | 예측 이동. 입력을 즉시 `shared/movement`로 적용하고, 서버 상태가 오면 서버 위치에서 아직 처리되지 않은 입력을 다시 적용해 보정한다. 그릴 때는 직전·현재 예측 위치를 다음 샘플까지 남은 비율로 보간한다 |
| 입력 시간 | 입력 하나는 클라이언트와 서버 모두 정확히 1/`inputSampleHz`초로 적용한다(그래야 예측이 서버와 어긋나지 않는다). 서버는 플레이어별로 실제 흐른 시간만큼(최대 `inputBudgetMax`초 쌓임)만 입력을 쓰고, 남은 입력은 다음 틱으로 넘긴다. 입력이 끊겨 쌓인 시간이 상한을 넘으면 넘친 시간은 서 있는 것으로 흐른다 |
| 내 손전등 조준 | 즉시 화면에 반영한다 |
| 다른 엔티티 | 약 100ms 지연된 두 상태 사이를 보간해 그린다 |
| 판정 | 피격, 줍기, 시선 정지, 사망, 라운드 결과는 항상 서버 결과를 따른다 |

### 3.4 연결 끊김

| 상황 | 처리 |
|---|---|
| 일시적 끊김 | 20초 안에 재접속하면 그대로 복귀한다. 그동안 캐릭터는 제자리에 남는다 |
| 20초 초과 | 사망 처리하고 소지품을 떨어뜨린다. 대기실이나 결과 단계였다면 방에서 제거한다 |
| 전원 퇴장 | 방을 삭제한다 |
| 서버 재시작 | 진행 중인 라운드는 사라진다. 클라이언트는 안내 후 첫 화면으로 간다 |

### 3.5 실행과 접속

| 단계 | 방법 |
|---|---|
| 개발 | 서버 `localhost:2567`, 클라이언트 개발 서버 `localhost:5173` |
| 친구 테스트 | 서버가 빌드된 클라이언트를 같은 포트로 제공한다. 그 주소 하나를 Cloudflare Quick Tunnel로 공개해 링크를 공유한다 |

### 3.6 최소 방어

방 코드 무작위 6자리, 서버 입력 검증과 범위 제한, 퀵챗·핑·깜빡이기 서버 쿨타임, 메시지 빈도 제한(초당 60개 초과분 폐기), 닉네임 길이 제한.

## 4. 화면, 조명, 소리, 조작

### 4.1 화면 구성

| 영역 | 구현 | 내용 |
|---|---|---|
| 게임 화면 | Canvas 2D | 기준 해상도 960×540, 창 크기에 맞춰 비율을 유지하며 확대·축소. 카메라는 내 캐릭터(유령이면 유령)를 따라간다 |
| 로비, HUD, 결과, 메뉴 | HTML/CSS 오버레이 | |

### 4.2 그리는 순서

1. 맵(층별로 오프스크린 캔버스에 한 번 그려 재사용)
2. 폐품
3. 캐릭터: 플레이어(색깔 원 + 방향 표시 + 이름), 추적형(검붉은 사각형), 시선형(창백한 세로 타원), 유령(반투명 원, 유령끼리만 보임)
4. 어둠 레이어
5. 효과: 핑, 깜빡임, 피격 시 화면 흔들림

캐릭터와 폐품은 "엔티티 종류 → 그리기 함수" 표로 그린다. 스프라이트 교체는 이 표만 바꾼다.

### 4.3 조명과 시야

| 광원 | 형태 |
|---|---|
| 플레이어 주변 빛 | 반경 1.5타일, 가장자리 흐림 |
| 손전등 | 60°, 8타일 부채꼴. `shared/vision`의 가시 다각형으로 벽에 막힌 모양을 만든다 |
| 고정 조명 | 원형, 벽에 막힘. 깜빡임 상태 반영 |
| 트럭 | 출입구 주변의 넓은 빛 |

| 규칙 | 내용 |
|---|---|
| 어둠 | 화면 전체를 거의 검게 덮고, 내 층의 모든 광원 영역을 뚫는다. 다른 플레이어의 빛도 포함한다 |
| 가시 조건 | 몬스터와 폐품은 광원 영역 안에 있을 때만 그린다 |
| 유령 시야 | 어둠이 옅어 맵 전체가 어둑하게 보이고 몬스터도 보인다 |
| 긴장 효과 | 같은 층 몬스터와의 거리가 5타일 이하이면 화면 가장자리 비네트와 심장 소리. 체력 1이면 가장자리가 붉어진다 |
| 성능 | 시야 계산은 미리 뽑아 둔 벽 선분으로 하고, 화면 안의 광원만 계산한다. 목표 60fps |

### 4.4 소리

| 소리 | 역할 |
|---|---|
| 추적형 발소리 | 접근 경고 |
| 시선형이 끌리는 소리 | 움직이는 중이라는 신호 |
| 동료 뛰는 소리, 폐품 줍기, 형광등 지지직 | 상황 정보 |
| 03:50 트럭 경적 | 종료 10분 전 경고 |
| 배경 웅웅거림 | 분위기 |

- Web Audio로 거리 감쇠와 좌우 패닝을 적용한다. 다른 층의 소리는 재생하지 않는다.
- 초기 소리는 CC0 효과음 또는 코드 합성음을 쓴다.
- Esc 메뉴에서 소리 켜기/끄기와 음량 조절을 한다. 설정은 브라우저 `localStorage`에 저장한다.
- 소리는 사용자가 처음 클릭한 뒤부터 재생한다(브라우저 정책).

### 4.5 HUD

| 위치 | 내용 |
|---|---|
| 상단 | 게임 시계, 트럭 총액 / 목표액, 현재 층 |
| 하단 | 소지품 3칸(선택 칸 강조, 가치와 무게), 체력, 스태미나 막대, 배터리 막대 |

### 4.6 조작 (PC)

| 키 | 살아 있을 때 | 유령일 때 |

| Shift | 뛰기 | 없음 |

## 5. 오류 처리

### 5.1 입장과 로비

| 상황 | 안내 |
|---|---|
| 서버 연결 불가 | "서버에 연결할 수 없습니다" + 다시 시도 |
| 없는 방 코드 | "방을 찾을 수 없습니다. 코드를 확인해 주세요" |
| 정원 초과 | "방이 가득 찼습니다" |
| 진행 중 | "게임이 진행 중입니다. 끝나면 다시 시도해 주세요" |
| 닉네임 규칙 위반 | 입력창 아래 즉시 안내 |
| 버전 불일치 | 입장 시 클라이언트가 빌드 버전을 보내고, 서버 버전과 다르면 "새 버전이 있습니다. 새로고침해 주세요" |

### 5.2 게임 중 연결

| 상황 | 처리 |
|---|---|
| 내 연결 끊김 | "재연결 중… (20초)" 표시와 자동 재시도. 성공하면 최신 상태로 즉시 맞춘다 |
| 복구 실패 | "연결이 끊겼습니다" → 첫 화면 |
| 동료 끊김 | "○○ 연결 끊김" 표시 |
| 탭 백그라운드 복귀 | 밀린 구간은 보간하지 않고 최신 상태로 즉시 이동한다 |

### 5.3 서버 방어

| 상황 | 처리 |
|---|---|
| 잘못된 형식의 메시지 | `shared/input` 검증 실패 시 버린다 |
| 범위 밖 값 | 허용 범위로 자른다 |
| 과도한 메시지 | 초과분을 버린다 |
| 서버 지연 | `step`에 넘기는 `dt`는 최대 100ms로 제한한다 |
| 규칙 실행 중 예외 | 해당 방만 "오류로 라운드가 종료되었습니다"를 보내고 대기실로 돌린다. 방 ID, 틱, 시드와 함께 로그를 남긴다. 다른 방에는 영향이 없다 |

### 5.4 규칙의 경계 상황

| 상황 | 처리 |
|---|---|
| 처리 순서 | 한 틱 안에서 입력 적용 → 이동 → 상호작용(줍기, 적재, 출발) → 몬스터 → 피해와 사망 → 시계와 라운드 판정 순으로 처리한다 |
| 벽 끼임 | 가장 가까운 이동 가능 칸으로 밀어낸다 |
| 마지막 생존자 사망 | 같은 틱의 트럭 출발 판정보다 먼저 실패로 처리한다 |
| 방장 이탈 | 게임은 계속되고 방장 권한만 넘어간다 |

### 5.5 맵 검증

서버 시작 시와 테스트에서 맵 JSON을 검사한다. 실패하면 서버가 시작하지 않는다.

- 시작 위치, 폐품 후보 칸, 트럭 구역, 경로 지점이 이동 가능한 칸에 있다.
- 모든 폐품 후보 칸에서 트럭 구역까지 경로가 있다.
- 계단이 층 사이에 짝지어져 있다.
- 폐품 후보 칸 수가 배치 개수보다 많다.

### 5.6 클라이언트 자원

| 상황 | 처리 |
|---|---|
| 효과음 로딩 실패 | 그 소리 없이 계속하고 콘솔에 경고 |
| 창 크기 변경 | 캔버스 크기를 다시 맞춘다 |

### 5.7 로그와 재현

서버는 방 생성, 시작, 종료, 오류를 방 ID, 틱 번호, 시드와 함께 기록한다. 결정적 규칙이므로 시드와 입력 기록으로 같은 상황을 테스트에서 재현한다.

## 6. 테스트 전략

### 6.1 단계

| 단계 | 대상 | 도구 | 방식 |
|---|---|---|---|
| 1. 단위 | `shared` 모든 모듈 | Vitest | TDD |
| 2. 시나리오 | `step` 다중 틱 | Vitest | 시드 + 스크립트 입력 → 결과 확인 |
| 3. 무작위 반복 | 라운드 전체 | Vitest | 시드 100개 × 무작위 입력 → 예외 없음과 불변 조건 |
| 4. 서버 통합 | Colyseus 방 | Vitest + `@colyseus/testing` | 가짜 클라이언트 1~4개 |
| 5. 클라이언트 단위 | 입력 변환, 보간, 예측 보정 | Vitest | 순수 함수 |
| 6. E2E | 실제 브라우저 | Playwright (헤드리스 Chromium) | 브라우저 2개로 방 생성 → 링크 입장 → 시작 → 이동 → 스크린샷 |
| 7. 직접 플레이 | 재미와 공포감 | 사용자와 친구들 | 체크리스트 → `config` 조정 |

### 6.2 단위 테스트 범위 (최소)

| 모듈 | 확인할 것 |
|---|---|
| `movement` | 벽과 차량을 통과하지 못함. 뛰기 > 걷기. 스태미나 0이면 뛰기 불가. 무게 감속 최대 30% |
| `vision` | 벽 뒤는 부채꼴 안이어도 안 보임. 60° 밖은 안 보임. 사거리 밖은 안 보임 |
| `noise` | 반경 안의 추적형만 감지 |
| `stalker` | 2.6의 모든 상태 전환 |
| `watcher` | 살아 있는 플레이어가 비추면 정지, 유령은 무효. 닿으면 즉사. 경로 없음 처리 |
| `items` | 3칸 초과 줍기 불가. 사망 시 소지품 낙하 |
| `round` | 04:00 트럭 밖 생존자 사망. 조기 출발 조건. 전원 사망 실패. 성공 판정 |
| `ghost`, `comms` | 쿨타임 |
| 난이도 | 2.5 표와 일치 |
| `input` | 잘못된 입력 거부, 범위 밖 값 제한 |
| `map` | 5.5의 검증 규칙 |
| `rng` | 같은 시드 같은 수열 |

### 6.3 시나리오와 불변 조건

- 시나리오: B가 시선형을 비추는 동안 A가 폐품을 실으면 총액이 늘고 둘 다 생존한다.
- 시나리오: 같은 시드와 같은 입력이면 결과가 같다.
- 불변 조건: 어떤 엔티티도 벽 안에 없다.
- 불변 조건: 트럭 총액 = 실린 폐품 가치의 합.
- 불변 조건: 사망한 플레이어는 폐품을 소지하지 않는다.

### 6.4 서버 통합 테스트 범위 (최소)

5번째 입장 거부, 진행 중 입장 거부, 20초 내 재접속 복귀와 초과 시 사망, 방장 이전, 잘못된 메시지에도 서버 유지, "한 판 더"로 같은 멤버 대기실 복귀, 버전 불일치 거부.

### 6.5 직접 플레이 체크리스트

- 어둠 속에서 무서운가? 소리가 경고 역할을 하는가?
- 시선형 때문에 "비춰줘!" 같은 협동이 생기는가?
- 03:50 경적 이후 "한 번 더 들어갈까" 고민이 생기는가?
- 먼저 죽은 사람도 유령으로 계속 즐거운가?
- 끝나고 "한 판 더"가 나오는가?
